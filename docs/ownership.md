# Ownership, provenance and IP defence

This page is the operational half of [NOTICE.md](../NOTICE.md) and
[LICENSE.md](../LICENSE.md): what the owner actually does, in what order, to be
able to prove authorship and stop a copy.

Nothing here replaces a lawyer. It is the evidence trail a lawyer needs.

## 1. What is protected, and by what

| Asset                    | Mechanism                                     | Where it lives                   |
| ------------------------ | --------------------------------------------- | -------------------------------- |
| Source code              | Proprietary licence + per-file banner         | This repository                  |
| Database schema          | Same licence, migration history               | `supabase/migrations/`           |
| Brand name, icon, lockup | Unregistered trademark + copyright + metadata | `apps/web/public/brand/`         |
| Copy (fr/ar)             | Copyright                                     | `apps/web/src/messages/`         |
| Design decisions         | Dated ADRs in git history                     | `docs/adr/`                      |
| Release artefacts        | SHA-256 hashes, signed tags                   | Outside the repo (owner's vault) |

Registration of the "EduRelay" wordmark and logo at INAPI (Institut National de
la Normalisation et de la Propriété Industrielle) is a **todo** before public
launch. Until then, the mark is used continuously and dated.

## 2. File banner

Every text file carries a banner generated by `scripts/header.mjs` from
`packages/brand/brand.config.json`:

- `/** … */` for TS/JS/CSS/SQL;
- `<!-- … -->` for Markdown;
- `#` for YAML/TOML/git files;
- `//` comments for tsconfig;
- a `"//"` key for strict JSON.

`pnpm headers` applies or refreshes it; `pnpm headers:check` fails CI when a file
is missing it. The banner is not decoration: it is the notice that makes an
unauthorised copy "knowing".

## 3. Repository hygiene

- The repository is private. Adding a collaborator requires the signed
  assignment in [CONTRIBUTING.md](../CONTRIBUTING.md).
- 2FA is mandatory on the GitHub organisation; no personal forks.
- Branch protection on `main`: signed commits only, linear history, CI green.
- Secrets live in environment variables, never in files. `.gitignore` covers
  `.env*`, `*.pem`, `*.key`, `*.p12`, `*.keystore`.
- `gitleaks` runs on every commit (pre-commit), on every push, and over the full
  history nightly. Config: [`.gitleaks.toml`](../.gitleaks.toml).
- Force-push and history rewrite are disabled on `main`.

## 4. Signed commits

Signed commits prove that a change came from a key the owner controls, which is
what makes a "this was my code" claim checkable.

```bash
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
git config --global tag.gpgsign true
git log --show-signature -1     # verify
```

Keep the private key offline (hardware token or encrypted archive). Publish the
public key on the portfolio (`sejed.dev`) and on GitHub so verification is
possible without contacting the owner.

## 5. Evidence trail

Do these once per release, store outside the repository:

1. `git tag -s vX.Y.Z -m "…"` and push the tag.
2. `pnpm release:hash` — writes `release-vX.Y.Z.sha256` plus a manifest of the
   tracked files and their hashes.
3. Copy the tag archive, the hash file and the manifest into the owner's vault.
4. Archive the original design sources (Figma `.fig`, raw SVG paths, font
   licences) with their metadata intact.
5. Note the date in the changelog. A dated, signed, hashed artefact is the
   strongest cheap evidence of priority.

The two brand SVGs keep their embedded C2PA provenance metadata. Do not run them
through an optimiser: the metadata is part of the record.

## 6. If a copy is found

1. Do not contact the person publicly. Preserve evidence first: full-page
   screenshots with URL and timestamp, `wget` mirror, DNS/WHOIS record, archive
   links.
2. Compare: file banners, commit hashes, unique strings, the generated brand
   token names, database enum ordering. Copies rarely remove every marker.
3. Send a dated cease-and-desist referencing the licence and the Tunisian law
   cited in it, with a deadline.
4. If money is involved, notify the host, the payment provider and the registrar.
5. Only escalate to counsel after steps 1–4 are documented in writing.
